# 方法与验证边界

OmniCommit 研究多语言、多说话人的增量 ASR：每轮只接收新音频，输出 `<|WAIT|>` 或 `<|DIRECT|>` 加新增的原语言文字。每次 DIRECT 开头带完整 `<语言><说话人>`；同次输出中归属变化时再次写完整前缀。WAIT 没有文本，之前暂存的内容须在之后有证据时输出。同一说话人更换语种不改变编号。

## 主线：文本标注与真实时间戳重铸

原始输入是一条音频与完整的带语种、说话人标签转录。文本教师一次调用产出 `segments`，其中每个 `source_text` 保留原文，包含源 WAIT 单元；标注时没有声学 0.5 秒边界。切分和动作由教师预测，可能漏标人名或数字，不能把它视作已验证声学事实。

真实音频对齐得到每个单元及必要的内部归属跨度 `start_ms/end_ms` 后，`build_asr_sft.py` 读真实音频时长，校验文本、标签和时间，将它们重铸到 0.5 秒或 1 秒音频网格。单元内如发生语种或说话人变化，必须有对应的带时间 `spans`；没有就拒绝该行，不从文字长度猜时间。参见 [时间戳直接生成 SFT](timestamped_to_sft_zh.md)。

当前重铸 v3 的动作规则：

1. 音频覆盖整个源单元后才可提交该单元；同块可以覆盖多个单元。
2. 真实语种或说话人变化在对应归属跨度**对齐起点**所在块触发 WAIT；不涉及切换的源 WAIT 在其结束所在块触发 WAIT。初始归属和相同前缀重复不是变化。
3. 触发 WAIT 的整块不提交，即使该块已完成后续 DIRECT。后续需要源 DIRECT 单元完成、且当前块没有新的等待事件，才一起释放已经完成的待提交内容；无新增文本的块同样输出 WAIT。
4. 真实音频结束后发送无音频的 `<end_of_audio>`；还有完成而未提交的内容就 DIRECT 释放，否则 WAIT。它不是第三种动作，也不是虚构的音频。

切换起点是文本归属跨度的对齐时间，不一定等于真实声学切换瞬间。原始输出没有 WAIT 原因，同一个单元同时含切换与实体时无法区分独立事件：实现按切换处理，不保证在实体完成时额外 WAIT。模型离线看到的是完整标注，而在线某个短块可能尚不足以判断实体或新声音，因此重铸结果只是监督策略，不能证明每个动作在线可识别。

同一行内时间戳路线的成功输出只包含 `audios/messages`：`audios` 是原音频的虚拟范围引用，不生成大量小 WAV；每轮 `<audio>` 与对应音频引用按顺序配对，最终 EOS 没有音频。输出清单 `.tokens.txt` 在 SFT 前用于注册动作、语种和说话人 token；`normalized`/`verbatim` 只更改指令，不转换原文。对至少 2 秒未标注区间写审查文件；无标注不等于静音。语义、时间与语音覆盖仍需听音抽查。

精简数据不保留安全拆窗所需来源元数据，不能直接送 `prepare_windows.py`；长样本必须先运行真实 SWIFT 模板长度检查。若需安全拆窗和因果说话人参照，使用保留完整元数据的分阶段路线。

## 独立对照：音频教师的稳定前缀

另一条路线是同一音频教师分别识别完整音频和累计音频前缀。教师调用不接收完整参考转录，也不强制继承上次识别；参考只供离线核对。以完整识别 F 为锚，每个时刻只考虑到目前为止完整输出 H_j 是 F 前缀的候选，选择最长者；归属属性逐字符比较，差分非空为 DIRECT，空为 WAIT。不能截取错误假设的正确开头冒充这一规则。

该路线可对 `normalized` 数字串和可选固定尾部做离线保守等待，但不能保证覆盖所有数量表达、姓名或实体，也不能把完整转录当作模型实时可见信息。这是与 [Confucius4-R2T2 的 whole-output final-anchored 思路](https://arxiv.org/html/2611.06043v1#S4.SS3)相关的独立对照，并非当前文本标注加时间戳重铸路线，也不声称复现论文的训练目标。该早期轨迹与当前 schema 2 路线的 EOS/格式不应混为一谈。

## 推理与长会议

Web 接收麦克风、系统声音或文件，逐块运行模型；会话保留有限音频历史、说话人参照和页面转录结果。待提交音频包含在有限历史中，当前没有独立的、可无限增长的待提交语音归档。人工参照需来自已听到的语音并带文字及编号；可选自动参照通过单独环境的 Qwen 强制对齐提出**实验性、未核验**候选，不能证明身份或排除重叠，阿拉伯语/泰语目前不会自动生成。网页不要求访问令牌；远程浏览器的麦克风和系统声音仍需受信任 HTTPS 或 localhost。见 [Web 服务说明](web_meeting_service_zh.md)。

当前 `verified` 上下文依靠人工或外部可信水位，未核验内容到预算时停止；`rolling` 使用启发式裁剪，可能遗漏长期挂起内容，连续 WAIT 超出预算亦会停止。说话人合并/更正主要作用于显示映射，并清理受影响参照，不会重写模型已收到的历史。缓存、0.5 秒识别、语言切换和 30 分钟长会稳定性均需使用真实模型和真实音频验证。

## 评估和因果边界

不能因为标签单调、时间戳合法或说话人编号连续，就认定转录、实体、数字和身份正确。线性转录不能完整表达多人重叠。应分别评估各语种 WER/CER、数字与人名准确率、语种/说话人归属、隔一段时间再次发言的身份、遗漏/重复、音频时间轴提交延迟及服务端延迟和积压；WAIT 比例只作诊断。

SFT 虚拟音频读取器先按源采样率截取音频，再独立重采样，避免整段重采样造成边界未来采样泄漏。文件 Web 路线先解码、按已播放边界截取、逐块重采样；压缩编码的解码依赖、音画偏移及重采样伪影需对真实媒体验收。CPU、replay 和模拟教师只能验证协议与数据流，不能证明真实 GPU 训练、真实转录质量或实时性能。
