# 音频前缀与切换时间：WAIT 数据构建设计

状态：历史讨论草案，不作为当前执行文档。现已实现 `collect_hf_prefixes.py` 与 `build_prefix_sft.py`，采用分语种累计教师、同语种换人保留上下文，以及兼容现有训练/服务的 DIRECT/WAIT 协议。以 [本地 Omni 前缀到 SFT](hf_prefix_sft_zh.md) 为准。下文取消 DIRECT、每轮末尾追加 WAIT 等设想尚未实现，不应混入当前训练数据。

## 当时讨论的任务条件

- 原始记录有完整音频和带语种、说话人标签的完整转录。
- 每个标签头也标记一个原始语义段；相邻相同归属标签不等于切换。解析时保留原始段边界、正文、空格、标点和顺序。
- 数据正在补充真实的语种/说话人切换时间；最终字段以用户实际 JSONL 为准，不提前假设字段名称、单位和时间原点。
- 教师在 GPU 服务器直接加载已做离线 ASR 微调的 HF 模型和配套 processor/tokenizer，正常转录累计音频。
- 最终学生每轮接收新增音频，输出新增带归属文字加 `<|WAIT|>`，或纯 `<|WAIT|>`。取消 DIRECT 动作。
- 先不增加专门的实体、数字识别与保护规则，但必须保留参考正文；数字格式变化仍可能导致文本对应失败，不能静默改写。

## 两种模型工作方式

教师标注输入为原始音频前缀 `audio[0:t]`，每次独立转录，不输入完整参考答案、未来音频或上一轮被强制固定的识别答案。教师不用事先学会 WAIT。

学生 SFT 输入为同一录音的连续新增块及已有对话历史。例如教师第 3 次听 0～1.5 秒，学生第 3 轮只新增 1～1.5 秒；此前声音由历史轮次提供。二者是不同训练构建阶段，不是将若干独立语种音频人工拼成会议。

HF 模型一次加载，整个作业复用。文本生成关闭音频输出；官方支持 `return_audio=False` 和禁用 Talker，具体调用按目标模型和已固定依赖验证。[Qwen3-Omni 官方说明](https://github.com/QwenLM/Qwen3-Omni)

现有 `HFBackend` 是已训练流式服务的后端，要求动作 token manifest；不能直接把它作为尚不具备 WAIT 能力的离线教师。教师需要独立入口和加载检查。

## 核心状态与不变量

构建器至少维护：

- 原文语义段及归属、可追溯的原文位置映射。
- 每次真实切换的唯一编号、原文边界、时间与标注质量。
- 每轮教师原始结果、解析结果及其与参考的对应状态。
- 当前候选可提交前缀、已提交位置、暂存部分。
- 所有已接收音频的真实时间边界，以及任何经过验证的安全裁剪位置。

必须满足：

1. 第 k 轮模型输入没有 k 轮之后的音频、参考答案或未来说话人参照。
   若使用下一轮结果确认前缀，最早只能在下一轮提交，不能把确认结果倒填到更早轮次。
2. 输出正文按参考顺序前进；不跳过未提交的中间文字，不重复已提交正文。
3. WAIT 表示本轮停止继续生成；它不取消之前已经输出的文字。
4. 多语种或多人可在同一条 assistant 正文中顺序出现；每次输出开头及内部真实归属变化处写完整标签。
5. 输出文字不等于整块音频已消费；有未提交声音时不能裁掉整个块。
6. 最后一轮只释放经完整音频及参考核对的内容；不能因为看到结束事件就补齐所有参考文字。
7. 结构检查不能证明声音、身份、语言或提交时机正确。

## 时间约定

内部统一使用相对于当前 `audios` 文件起点的源音频采样位置，并保存毫秒显示值。外部时间若相对原始长录音，必须有明确片段偏移才能换算。

新增块使用左闭右开区间 `[start, end)`。切换时间恰好等于块末端时，归入下一块；不能相邻两轮重复触发。首次归属初始化不作为切换。语种与说话人同时变化可以是同一个切换事件，记录两种变化属性。

同块多次切换全部登记。重叠说话不能当作一个精确的单人切换点；当前第一版应进入复核或单独路线。

普通步长候选为 0.5、0.8、1.0 秒，每个实验配置固定。末块使用真实剩余长度，不丢掉、不复制音频；如模型编码需补零，补零不属于新增源音频时间。

## 提交位置的判定

### 教师证据与参考对应

保存教师未经修复的原始输出，再进行格式解析、原文顺序对应、完整识别与参考核查。不能用简单的包含关系定位重复的“好的”“yes”等短语，也不能只用一个整段相似度分数放行切换附近错误。

正文对应和归属核对分开记录。参考标签是监督目标，教师的 speaker 编号不是跨请求固定的全球身份。可处理明确的编号置换，但不能只因编号连续就认定声音身份正确。文字唯一对应也不能证明声学身份已经可靠识别。

规则需在实现前确定单一版本：例如基于整个教师假设的前缀可接受性，或连续前缀局部一致性。不能在不同样本中无记录地混用。连续两轮一致仅是证据，不是正确性证明。

R2T2 的整条假设前缀准则与相邻假设的公共前缀不同；再叠加我们的切换截断后，目标也不一定仍等于某个完整教师输出，因此应标明为本项目改造，不宣称原样复现。[R2T2 方法](https://arxiv.org/html/2611.06043v1#S4.SS3)、[Whisper-Streaming](https://aclanthology.org/2023.ijcnlp-demo.3/)

### 切换时间提供的约束

- 尚未到达的切换：不允许提前提交该边界后的新归属内容，即使教师已经猜出了后文。
- 本轮跨过的切换：按当前选定策略，最多提交到本块最早切换前的原文边界；只提交其中已确认而未输出的文字。
- 切换后的后续轮：该边界不再重复限制；内容通过核对后可释放，无须等待出现另一个新词或另一个所谓 DIRECT 单元。
- 后续轮又出现新切换：允许释放更早已确认的积压，但仍不能越过本轮新的受限边界。
- 同块多次切换：当轮限制到最早边界，全部登记；后续可在一条输出中释放多个已确认归属片段。

这是明确的保守提交策略，不表示任意切换都声学不确定，也不保证仅等待一轮就足够。先以固定策略建立基线，后续再对比不同等待策略。

### 无法由切换时间解决的问题

单一语种、单一说话人的长段内部没有新的切换时间。模型可能补出未来恰好会说到的文字；完整参考匹配、重复两轮一致、甚至全句锚定前缀一致都不能单独排除这种情况。

用户提供的阿拉伯语样例含固定经文式内容，朗诵、歌词、背诵及常见固定表达应重点检查提前补全。对这类高风险数据，可以补充语义段结束锚点、局部字词时间或人工核验前缀。语义段结束锚点只能提供较粗约束，不能替代段内每个词的完成时间。没有这些证据时必须保留“时机未经充分验证”的数据质量状态，不能把候选数据宣称为声学真值。

## 场景清单

| 场景 | 期望处理 |
|---|---|
| 普通位置有新增且可确认文字 | 提交新增部分，然后等待下一块 |
| 普通位置尚无可提交文字 | 纯等待，不编造内容 |
| 同归属重复标签形成新语义段 | 保留语义边界，不触发切换等待 |
| 同块包含旧语言末尾与新语言开头 | 提交可确认的旧语言末尾，暂存新语言开头 |
| 同块包含旧说话人末尾与新人开头 | 提交可确认的旧说话人末尾，暂存新人开头 |
| 切换前没有尚未提交的文字 | 当轮纯等待 |
| 同时换语言、换人 | 一次事件保留两个变化属性 |
| 同块发生多次切换 | 全部登记，当轮限制到最早边界 |
| 切换恰在块起点或末端 | 按统一半开区间只归属一个块 |
| 下一块没有新词或是静音 | 仍可释放上一轮已确认的积压，不要求再有新词 |
| 多轮后仍然不能对应参考 | 复核/过滤，不把教师错误统统转为长串等待 |
| 识别到未来归属文字 | 按真实切换时间阻止提前跨边界 |
| 同归属内部提前补全 | 切换时间无法解决，需要额外时序证据或复核 |
| 教师输出翻译而非原语言转录 | 标记教师失败，不把译文当作 ASR 目标 |
| 教师回改已提交部分 | 记录冲突，不能靠强制旧答案掩盖；按规则复核样本 |
| 短句重复、含糊插话、多人同说 | 不强行按文本相似位置分配说话人 |
| 模型空输出、生成截断或 OOM | 记录推理错误；不自动伪装成有效等待 |
| 末尾不足一个完整块 | 保留真实尾块与真实时间 |
| 真实结束仍有待提交内容 | 核对后释放；持续冲突样本复核/拒绝 |
| 只有静音 | 与“语音转录失败”区分，使用单独可验证来源 |
| 长时间后旧说话人回来 | 原编号加过去的可靠声音参照，独立评估身份一致性 |

## WAIT 输出协议

普通音频轮次的目标为以下一种：

```text
<zh><spk1>已经确认的新文字<|WAIT|>
```

```text
<|WAIT|>
```

同一条正文允许有多个完整归属头。WAIT 不作为显示给用户的转录正文；每次碰到它停止本轮解码，保留前面的文字。普通轮次统一以 WAIT 交还控制权，是本项目的协议约定，不等于论文所有训练目标都追加 Wait。

真实结束使用项目的无音频结束事件，目标为核对后的剩余正文加正常 chat EOS；无剩余时为 EOS-only 目标。实现时必须验证 SWIFT 模板确实为结束目标产生监督 token，且不会把空 assistant 内容作为坏行或无监督样本丢弃。这一终止轮约定尚未通过真实训练模板验收。

新的 token 清单使用 WAIT、所需语言和说话人标签。加载已有 tokenizer 时不删除或重排旧 DIRECT token，避免改变既有 ID；新数据可以不使用 DIRECT。训练前注册所需 token 并保存对应权重，导出和推理保持同一词表。

## 后续脚本的建议职责

以下名称是设计建议，尚未创建这些入口。

### 1. `collect_hf_prefixes.py`

输入原始 JSONL、模型目录、音频根路径/映射、步长、GPU 与生成配置。原始时间字段先通过适配层规范化。

输出逐条前缀轨迹，记录输入指纹、音频真实采样率/时长、每轮端点、教师原始文本、解析状态、耗时、失败情况及模型配置指纹。模型正常转录，参考只供程序侧核查。

模型在进程内只加载一次。纯 HF 多 GPU `device_map` 是模型放置方式，不自动等于高效并行推理；先测量吞吐再定批量。解码时保留语言/说话人标签，只移除明确的 chat 包装；不能因 `skip_special_tokens=True` 把已注册归属标签一并删除。

从源采样点截取前缀，再独立重采样，避免先处理完整未来波形再切块引入边界泄漏。不要在每个前缀重复从磁盘读取完整录音；可复用源波形，不能未经验证复用会受未来影响的音频特征/KV cache。

### 2. `build_wait_sft.py`

输入原始记录、真实切换标注和前缀轨迹；纯 CPU 状态逻辑，不再次调用 Omni。

输出精简训练 JSONL、有序 token 清单、拒绝记录、复核记录和汇总。每个新增音频块一个 user/assistant 轮次，保留源音频虚拟引用。来源映射与诊断另存，不塞进模型输入。

保留富中间轨迹，便于安全拆窗与说话人参照构造；最终精简训练数据不应成为唯一可追溯来源。

### 3. 审计与回放

结构检查、音频解码、实际 HF/SWIFT 模板长度检查与真实样本回放分开。回放能展示某轮实际听到的声音、切换位置、教师输出与提交目标。模拟测试不替代听音。

## 容错、恢复和资源边界

- 单条解析、标签、时间或音频错误，记录并继续其余记录。
- 推理错误记录为错误，不生成假 WAIT。若重试，次数与条件显式配置并写日志。
- 按记录和前缀进度保存，恢复前核对源数据、模型、prompt、步长及配置指纹，防止混合不同实验。
- 已完成前缀不重复计算；已有结果不静默覆盖，不自动备份。
- 磁盘满、无法写结果、模型整体加载失败等作业级错误必须明确报告；继续打印“成功”会产生无法审计的数据。
- 输出和日志使用用户指定的 `/data` 绝对路径，启动时打印实际解析路径并验证可写。
- 长录音会使累计前缀处理成本增长。没有安全语音边界和参考缓存时，不任意拆成无关短样本或静默截断。
- 学生训练窗口必须经过真实模板长度检查；保留待提交内容和过去的可靠说话人参照，不从未来取声音。
- 对照实验应统一前缀采集、训练样本和服务端的音频步长，分别记录 0.5、0.8 和 1.0 秒的结果。

## 验收顺序

1. 合成时间/文本状态测试：覆盖上述边界、重复标签、多次切换、无新词释放、尾块和结束事件，不需要真实模型。
2. 代表性真实录音回放：单语、混语、多人、固定文本、噪声、重叠、长间隔回归，逐语种统计错误与数据保留率。
3. HF 小批实测：记录 GPU、batch、输入长度、输出长度、墙钟耗时、显存及失败率，区别生成耗时与音频时间轴提交延迟。
4. SFT 模板审计：新 WAIT 协议、EOS-only 结束轮、动作/归属 token、loss mask、虚拟音频与长度都通过真实环境验收。
5. 小规模流式 SFT 后，对真实新增块推理评测；不能仅凭教师累计前缀表现宣称学生交错流式模式已有效。

当前输入足够开始采集和构造候选数据。正式放行标准须结合这些试验确定，不能在尚未听音与测量前设定未经验证的质量保证。
